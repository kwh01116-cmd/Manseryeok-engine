## 2026-10-20 — API 키를 확보했지만, 바로 엔진에 붙이지 않기로 한 이유 (대화 기반 계획 기록)

## 2026-10-20 — G1-P1: 출처 검증의 '보장 범위'를 코드로 제한

**[문제]** G0는 명식 계산의 내부 일관성을 보호하지만 절기·음력 행 86개의 원본 판본 인증까지 해주지는 않는다. KASI API 인증키 등록 환경도 저장·게시 오류를 겪고 있었다.

**[시도와 결정]** API 호출을 기다리지 않고 별도 report-only 자료 감사 모듈, 독립 row manifest, 변조 테스트를 먼저 만들었다. **원본 행 86건은 모두 UNVERIFIED**, 연간 페이지의 V1.0a 정보는 *후보 판본 메타데이터*라고만 표현하고, 가짜 문서 지문이나 상업적 승인 표시를 거부했다.

**[실제 변경]** [코드 커밋 4efa763](https://github.com/kwh01116-cmd/Manseryeok-engine/commit/4efa763edab36b5386a5d51ee2c838e131f90694). 새 JavaScript 감사 모듈, 49개 절기·37개월 row-identity manifest, 9개 테스트 그룹. 기존 M1·G0·M2·UI는 미변경.

**[실제 검증과 한계]** Node 22.16.0, 별도 재구성한 fixture 49+37건의 두 SHA-256이 저장소 원본 pin과 일치하는 상태에서 집중 테스트 **9/9 PASS**. 직접 GitHub checkout 불가(DNS) 때문에 저장소 전체 npm run check와 브라우저 검사는 **미실행**. 이전 283개 테스트의 통과를 신규 코드에서 재검증했다고 주장하지 않는다.

**[다음 작업]** Codex 실행환경의 exact-checkout 전체 검사 → 원본 자료의 실제 행별 판본 검증 → 필요시 G1-P2 신뢰 경계 연결. KASI API 키·새 연도·Story 화면·상업 배포는 보류. [상세 보고서](engineering/G1_P1_EVIDENCE_AUDITOR_EXECUTION_20261020.md).
