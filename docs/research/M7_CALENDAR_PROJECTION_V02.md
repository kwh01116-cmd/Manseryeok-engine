# M7 v0.2 — 명목 교운일·기간표·조회 정책

정책 **`M7-CALENDAR-NOMINAL-YMDH-SEQUENTIAL-CLAMP-V02`**, 버전 **0.2.0**은 검증된 v0.1 기산의 정수 분 간격을 Gregorian 달력으로 투영하는 **이번 프로젝트의 선택형 산술 규칙**이다. 기존 `M7-TRADITIONAL-YEAR-STEM-JIE-3D-V01`의 의미·방향·순서·절입·분 간격·유리수 나이·동분/결손·세운을 소급 변경하지 않는다. 명목 교운일은 해당 입력과 정책에서 재현되는 날짜이며, 측정된 교운 순간·전통 전체의 유일한 정답·미래 사건의 예측값이 아니다.

## 정수 단위 분해와 첫 명목 교운일

기산 상태가 **OK**인 기존 정수 분 간격 M>0에만 다음 분해를 적용한다.

```text
Y  = floor(M / 4320)
r1 = M mod 4320
MO = floor(r1 / 360)
r2 = r1 mod 360
D  = floor(r2 / 12)
H  = 2 × (r2 mod 12)
```

이 단위가 실제1년=360일을 뜻하지 않는다. 원래 `M/4320 MODEL_YEAR`와 약분값도 보존한다. 표시 소수를 역산하지 않는다. `decomposeLuckMinutes`의 수학적0분 분해는 가능하지만, OK 기산의 달력 투영은 양수 M·원래 유리수·선택 절입 간격의 일치를 요구한다. 같은 분의 AMBIGUOUS 진단0분은 날짜가 되지 않는다.

변환이 끝난 **실제 기록 양력 출생 분**에서 Y년→MO개월→D달력일→H시간 순으로 더한다. 년/월 단계는 목표 월에 원래 일이 없을 때만 말일로 제한한다. 일·시는 기존 Gregorian day-number 함수로 이동하며 PC 시간대를 읽거나 문자열을 암묵적 Date로 파싱하지 않는다. 각 단계의 입력/출력·양·요청 일·목표 월 길이·제한 여부를 남기고 출생 시각의 분을 유지한다. 입력 자체가 잘못된2월30일이면 거절한다.

| 독립 손계산 입력 | 분해 Y/MO/D/H | 년→월→일→시 최종값 |
| --- | --- | --- |
|2026-06-01 12:00, M=6528 |1 /6 /4 /0 |**2027-12-05 12:00** |
|2026-06-01 12:00, M=38351 |8 /10 /15 /22 |**2035-04-17 10:00** |
|2020-02-29 12:37, M=4680 |1 /1 /0 /0 |**2021-03-28 12:37**. 년 단계에서2월28일로 제한한 뒤3월28일이 됨 |

마지막 사례에서13개월을 한 번에 더하면2021-03-29가 될 수 있지만 이번 순차 정책과 다르다. 기대값을 구현에 맞춰 바꾸지 않고 각 단계의 손계산 값을 테스트로 고정했다.

### 비단조 반례를 보존

2026-01-31 12:00에서 **M=359**는0년0개월29일22시간으로 **2026-03-02 10:00**, **M=360**은0년1개월0일0시간으로 **2026-02-28 12:00**이다. 간격이1분 늘었는데 명목 날짜는 앞당겨진다. 모형 월과 실제 Gregorian 월 길이가 다르기 때문에 발생하는 이 정책의 성질이다. 보정·정렬·clamp로 숨기지 않았고 독립 기대값으로 검사한다. 따라서 분해 경계를 매끄러운 물리적 시간변환이라고 홍보할 수 없다.

## 기간표와 조회 범위

첫 명목 교운일 S를 기준으로 k=0부터 `start[k]=S+10k년`, `end[k]=S+10(k+1)년`을 **각각 직접** 계산한다. 기간은 `[start,end)`이며 간지는 기존 순서의 k번째다. 바로 앞 경계에 다시10년을 더하는 반복 방식을 쓰지 않는다.

S=**2000-02-29 12:00**이면 +10년은2010-02-28, +20년은2020-02-29다. +10년의 제한 결과에서 다시10년을 더한2020-02-28은 이번 정책의 두 번째 경계가 아니다. 인접 end/start는 같고 각 후보의 표는 엄격 증가·비중첩·무결손이다. 기존10모형년 구간은 별도로 보존하며 실제 만 나이·세는나이로 재명명하지 않는다.

| 범위 | 계약 |
| --- | --- |
| 기존 출생 명식 |양력 환산 `[1989-01-01,2027-01-01)`, 기존 API 프로필/4일주시주 정책. 확대하지 않음 |
| 순수 달력 산술/명목 기간 생성 |proleptic Gregorian **0001-01-01T00:00~9999-12-31T23:59**. 년·월·일·시간 가산이나 표 끝이 범위를 넘으면 명시적으로 거절 |
| 실사용 as-of |**[1989-01-01T00:00,2027-01-01T00:00)**의 날짜·시각 필수. 범위 밖은 POLICY_UNRESOLVED이며 미래 명목 표의 존재로 법정시/DST 검토 범위를 확대하지 않음 |
| 세운 |기존 v0.1 조회와 별개.2027 라벨 산술과 실제2027 입춘 자료 부족을 혼동하지 않음 |

미래 기간표에는 미래 절기 API가 필요하지 않지만 그 날짜의 법정시·DST·세운을 인증하지 않는다. UTC 순간을 만들지 않는다. 정밀도는 원자료 MINUTE, 결과 의미는 `NOMINAL_UNDER_SELECTED_POLICY`다. 알려지지 않은 초·반올림에 ±30초·확률을 붙이지 않는다.

선택 함수는 정책/분 입력 검증→조회 범위 확인→기산 AMBIGUOUS/NEEDS_DATA 전파→BEFORE_BIRTH→BEFORE_FIRST_DA_YUN→반개구간 선택/OUTSIDE_GENERATED_RANGE 순으로 판정한다. 정확히 경계 분이면 새 구간을 선택한다. 첫 대운 전 소운이나 표 끝을 넘은 마지막 대운 반복은 없다. 범위 밖 조회가 정책 보류인 것과 기산 자료 부족은 다른 층이다.

각 후보의 입력·방향·절입·기산·첫 날짜·기간표·조회 결과는 같은 후보에 묶는다. 두 원국 후보나 독립 세운 결과를 확률 또는 Cartesian product로 합치지 않는다. 기존2026말 순행은2027소한이 없어 날짜/표/조회도 NEEDS_DATA를 유지하며 기존 fixture·새 API·manifest 수정으로 메우지 않는다.

## 구현·검사 경계

순수 모듈은 기존 `gregorianDayNumber`/`gregorianDateFromDayNumber`,60갑자 검증/순서 함수를 재사용한다. 년0001~0099도 기존 UTC setter 기반 day-number 함수로 검사해 `Date.UTC`의0~99년 특이 동작을 피한다. 새 일반 시간대·역법·규칙 프레임워크는 없다.

`projectNominalLuckCalendar`는 기존 기산과 양력 분·방향·정수 M·M/4320·절입의 구조적 연결을 확인한다. same-process의 작은 발급 집합은 불변 투영 객체/기간표 복제·변조를 거절하는 산술 연결 장치이며 외부 출처 인증이 아니다. 검증된 M1/v0.1/API 후보의 실제 발급 및 source/policy/candidate 연결은 기존 로컬 어댑터가 별도로 확인한다.

`test/m7-calendar-projection-core.test.mjs`의12개 집중 그룹은 두 승인 예시,0/1/11/12/359/360/4319/4320/4321분, 비단조 반례, 순차/복합 차이, 말일·윤일·2000/2100/2400년, 일/시의 연말 이동,0001/0099·상한 overflow, 최초 윤일 기준 직접 가산, 첫/각 전환의 전·동일 분·후, 출생 전/첫 전/표 밖, 조회 범위, 미확정·자료 부족, 원래 정수/분수/절입/정책/후보/표 변조·복제 거절을 독립 리터럴 기대값으로 검사한다. 초안 Node22 집중12/12은 최종 코드 SHA의 전체 회귀·브라우저·비공개 수락 검사와 구분한다. 최종 실제 검사/실행 SHA는 별도 실행 보고서를 따른다.

신강약·격국·용신·합화·길흉/개인 사건, 역사시 확대, 최종 서비스 기본 정책 채택, UI/공개 배포는 이번 선택형 정책의 완료 범위에 없다.
