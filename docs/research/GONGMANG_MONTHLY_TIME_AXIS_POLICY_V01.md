# 공망·월운 계산 정책 v0.1

2026-11-14. 이 정책은 존재·간지·시간축 계산이다. 공망의 실제 길흉, 월별 사건, 생조/강약 효력은 구현하지 않는다. 기존 일주·시주 교체·월주·년주 정책의 의미를 바꾸지 않는다.

## 일주 기준 공망

`M2-DAY-XUN-VOID-BRANCHES-V01` / `0.1.0`, 스키마 `day-xun-gongmang-v1`.

이미 M1이 선택한 일주가 속한 10간지 순을 찾고, 그 순의 열 지지가 사용하는 집합에서 빠지는 두 지지를 반환한다. 기존 `SEXAGENARY_CYCLE`/`ganZhiIndex`/`ganZhiAt`와 지지 목록을 재사용한다. 새 장간표·가중치·천문 계산은 없다. 일주를 다시 계산하거나 자시의 유효 날짜를 임의로 선택하지 않는다.

| 기준 순 | 공망 지지 |
| --- | --- |
| 甲子 | 戌·亥 |
| 甲戌 | 申·酉 |
| 甲申 | 午·未 |
| 甲午 | 辰·巳 |
| 甲辰 | 寅·卯 |
| 甲寅 | 子·丑 |

이는 선택한 일주 기준에서의 유한 순환 산술이다. 별도의 년주 공망·다른 공망 학파를 통합한 정의가 아니다. 기술 대조는 기존 OSS 감사의 고정 [manseryeok fba3253](https://github.com/yhj1024/manseryeok/blob/fba3253d7305b8b61189bd78318a7a27ed8c9b09/src/features/void-branches.ts) 실제 함수와 기존 순환 배열이며, 외부 소스 코드를 복사하지 않고 집합 차 산술로 작성했다. 원전/주석의 공망 효력이나 판본·권리를 새로 인증했다고 하지 않는다.

네 원국 지지는 위치별 PRESENT_UNDER_POLICY/ABSENT_UNDER_POLICY로 표시하고 반복 지지를 보존한다. 입력 네 기둥/필수 참조가 빠진 것은 공망 부재로 바꾸지 않는다. 대운·세운·월운에 쓸 수 있는 별도 위치 타입은 원국의 다섯째 기둥으로 추가하지 않는다. 공망 대응이 있다고 기존 장간·통근·격국 후보를 삭제하거나 길흉을 부여하지 않는다. `efficacy=NOT_EVALUATED`다.

## 절입 기준 월운

`M7-MONTHLY-TWELVE-JIE-PUBLISHED-MINUTE-V01` / `0.1.0`, 스키마 `monthly-jie-luck-v1`.

기존 `resolveYearMonthPillars`, 입춘 년주 resolver, `monthPillarFromYearStem`, 12절입 분류와 날짜 검사를 재사용한다. 매월1일·음력 초하루·음력 설을 새 경계로 삼지 않는다. 사용자가 지정한 시각의 양력 달(`gregorianCalendarMonth`), 입춘 기준 연도 라벨·연주, 실제 절입 기준 월운·월간지·시작/종료 이벤트를 나눈다.

연도표의 `yearLabel=2025`는 **2025 입춘의 寅월부터2026 입춘 직전의 丑월까지**다. 양력2025년1월~12월 표가 아니다. 2026년1월 소한 뒤의 己丑월은 이 표의 열두 번째 구간이다. 표는 명목 반개구간으로 표시하지만, 같은 발표 분의 시각 조회를 그 표에 강제로 한쪽 배정하지 않는다. 표시 분의 전/후 상관 후보는 기존 resolver 그대로 유지한다. 입춘에서는 연주/월주가 함께 변하는 두 상태만 나오며 네 조합을 만들지 않는다.

조회 범위는 기존 현대 민간시 `[1989-01-01T00:00,2027-01-01T00:00)`다. 출생 범위와 독립 달력 조회, 필요한 경계 자료를 구분한다. 이전1988 대설은 원래 프로필의 보조 경계 용도만 유지한다. 2027 이벤트/조회 시계 정책이나 역사 DST를 자동 채택하지 않는다. 순수 타임라인 검사는 KST·MINUTE·실제 절기명·유일 sourceIds·엄격한 시간순·연도와 절입의 연속성을 요구한다. 자료 중간의 절입 누락은 건너뛰지 않는다.

| 경우 | 결과 |
| --- | --- |
| 검증한 조회 연도의12절입·이전 대설이 없음 | NEEDS_DATA, 필요한 연도/절기 목록 |
| 같은 발표 분 | AMBIGUOUS와 전/후 월운 후보 |
| 현재 월간지는 확인됐지만 다음 종료 경계만 없음 | PARTIAL, 월간지는 유지·종료시각=null·부족 이벤트 명시 |
| 연도표 일부 시작/종료 경계 없음 | 행별 NEEDS_DATA와 표 PARTIAL/NEEDS_DATA |
| 유효한2027 이후/1988 이전 조회 | POLICY_UNRESOLVED, 현재 시계 정책 범위 밖 |
| 잘못된 날짜·정책·source/순서·sparse 입력 | 명시적 입력 거절 |

현재 base만으로2025 표는12구간이 완비된다. 2026 표에서는 대설~2027소한의 종료 경계와 2027소한~입춘 구간이 부족하다. 간지 순서 자체는 기존 년간 산술로 표시할 수 있지만 실제 경계 날짜를 만들어 채우지 않는다. 기존2027 fixture나 supplement를 숨은 fallback으로 사용하지 않는다. 별도 보강 자료를 선택하더라도 조회 시계 정책 승인이 따로 필요하다.

`createLocalMonthlyLuck`는 발급된 로컬 프로필의 이벤트 문맥을 한 번 준비해 재사용하며 출생M1 계산을 호출하지 않는다. 기존 M1 결과를 연결할 때 live 발급·dataset/profile 문맥을 검증한다. 독립 월운 조회를 원국 후보와 곱집합으로 만들지 않으며, 조회가 출생 전이면 BEFORE_BIRTH를 별도로 표시한다. API 원문 표기·sourceRef·분 정밀도는 `sources[].evidence`에 보존한다. KASI는 경계 계산의 출처이며 공망/길흉 이론의 저자가 아니다.

## 기대 계약과 검증 수준

[기대 fixture](../../test/fixtures/gongmang-monthly-expectations-v1.mjs)는 resolver 작성 전에 공망60개·2025/2026 월간지12개씩·입춘/경칩/1월의 독립 리터럴을 고정했다. 최초 LF 정규화 SHA256 `23a1ac028c19a775a6103eac3cf0d268e4b95ae2b0eaf61a44853c4f12fcced3`를 테스트에서 검사한다. Windows checkout의 CRLF만 동일한 LF로 바꾸며 입력·기대 내용을 정규화해 바꾸는 것은 아니다. 합성 이벤트 날짜는 실제 API 발표 시각으로 주장하지 않는다. 유한 순환/정책 검사, 기존 resolver 연결 검사, 실제 비공개 자료 연결 검사를 분리한다.

실제 base 파일럿에서는2026-01-08 壬午의 申酉 공망·원국 대응0,2026-01-12 丙戌의 午未 공망·시간午 대응1, 입춘 두 원국의 별도 대응을 확인했다. 실제2025 월운12구간의 간지를 사전 리터럴과 대조했고2026 부족2구간/2027 정책 보류도 유지했다. 파일럿은 최종 전체 회귀나 독립 천문·예측 검증을 대신하지 않는다. 최종 SHA·실제 실행 수는 Sprint3 실행 기록에서 별도로 확정한다.
