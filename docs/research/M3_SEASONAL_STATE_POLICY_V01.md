## 프로젝트가 선택한 월 구간과 보류

「論地支」에는 寅·卯의 봄, 巳의 초여름, 午의 여름 열기, 辰·未의 계절말 등 월 문맥이 있다. 다만 다음의 **8월 지원/4월 보류 계약 전체**는 이번 프로젝트가 명시적으로 선택한 제한이다. 문헌이 네 계절말 월의 판단을 모두 보류하라고 직접 명령한 것으로 표시하지 않는다.

| 입력 후보의 사주 월지 | 이번 정책의 구간 | 결과 |
| --- | --- | --- |
| 寅·卯 | 봄 | `RESOLVED_UNDER_POLICY` |

이 월지는 기존 절입 resolver가 해당 후보에 계산한 월지다. 양력 월 번호·음력 월 번호·기상 계절로 대체하지 않는다. 입력된 명식의 월주나 적용 절입을 다시 계산하지 않는다. 일별 사령, 18일/30일 배분, 지장간 용사 일수, 연속 세력·점수·가중치와 得令 이진 라벨은 만들지 않는다.

**土 일간과 土 월지 보류는 다르다.** 戊·己는 여덟 지원 월에서 위 土 열로 정상 분류한다. 예를 들어 寅월 土는 死다. 辰·未·戌·丑월은 일간의 오행과 관계없이 이 판단 항목만 보류한다. 나머지 원국·장간·통근 검토 후보·지지 관계·적용 절입은 계속 제공한다. 정책 보류를 API 결손·출생 범위 밖·전체 명식 미지원으로 바꾸지 않는다.

## 판단과 설명의 계약

순수 입력은 같은 후보의 일간 오행·월지·명시한 정책·연결할 근거다. 분류 자체는 같은 오행이면 음양에 관계없이 같으며, 다른 기둥·장간·통근 후보·지지 관계·성별·대운·세운·조회 시각으로 달라지지 않는다. 실제 자료의 진위는 순수 함수가 인증하지 않는다. 로컬 어댑터는 기존 발급 M1/M2/M3의 같은 실행·후보 연결을 확인한다.

구조 근거는 기존 `EVIDENCE_ONLY`로 남고 새 계절 판단만 별도 상태를 갖는다. 원래 구조 근거의 계절 효력·사령 미해결 상태를 소급 변경하지 않는다. 새 판단은 정책/규칙/스키마 버전, 후보와 월지, 오행별 상태·일간 상태, 입력 evidence/fact 참조, 적용 절입·KASI 계산 출처, 위 문헌 출처·프로젝트 정의를 구분해 남긴다. 설명은 판단→정책/규칙→입력 근거→후보를 가리킨다.

입춘 표시 분의 己丑/庚寅 두 후보에서는 전자는 정책 보류, 후자는 봄 표의 土死다. 한 후보를 다른 후보에 대입하거나 첫 후보를 선택하지 않는다. 死·囚는 전통 분류 이름이며 사람의 죽음·질병·수감·불행을 뜻하는 문장으로 번역하지 않는다. 수치 강도·신강/신약/중화·길흉·용신·격국·유효 통근·합화·관계 효력을 이 결과에서 만들지 않는다.

## 독립 검사 계약과 확인의 한계

독립 기대값은 위 20셀과 명시적인 10일간×12월지 120조합이다. 순수 조합에서는 정상 분류80·계절말 보류40이며, 이는 가능한 완전 출생 명식120개라는 뜻이 아니다. 丙/巳·丁/巳=여름 火旺, 丙/子=겨울 火死, 戊/寅=봄 土死, 庚/酉=가을 金旺, 癸/卯=봄 水休를 별도 고정 사례로 둔다. resolver나 오행 helper의 출력으로 기대값을 생성하지 않는다.

실제 1989~2026 API 후보의 많은 입력은 월지·일간·후보와 참조가 이 정책에 제대로 연결되는지 검사한다. 그것은 문헌 해석의 독립 정답·예측 효력·권리 인증이 아니다. 실제 실행 수·상태 분포·SHA·실패·브라우저·CLI 결과는 실행 보고서에서 확인하며, 이 정책 문서만으로 실행 통과를 주장하지 않는다. 원본·후보·2027 supplement는 읽기 전용이며 이 모듈은 supplement·KASI 요청·키·네트워크를 필요로 하지 않는다.
