## 1989년 초와1988년 말 guard의 판단

1989년의 폐지일은5월8일이므로 단순히 “1989년1월1일부터 폐지”라고 기록하면 사실과 다르다. 폐지 전 기존 규칙도 겨울에는 DST를 적용하지 않으며, 그해 예정 시작일보다 앞서 폐지됐다. 따라서1989년1월~폐지일에도 추가1시간은 없다. 이후 현대 범위도 기존 한국 시간 코드/공식 연혁과 고정 IANA 자료에서 동일한 표준시 사용으로 확인된다.

기존 `src/time/koreanDst.ts`는1988년 DST 종료를 `1988-10-09T03:00:00` daylight에서02:00 standard로 정의한다. 이는 제정령에 대한 기존 저장소의 검증 기록 및 위 고정 IANA 규칙과 일치한다.12월 대설은 그 종료일보다 뒤에 있으므로 +09:00 표준시와 한국 민간시가 일치한다. 이 한 보조 이벤트를 비교하는 데1988년 여름의 gap/fold 해결이 필요하지 않다.

1988년 대설 원문의 `kst` 분은 검증된 후보의 원래 날짜·시각에서 가져와야 한다. 이 문서가 시각 숫자를 새로 계산하거나 연간 TXT에서 채워 넣는 것은 아니다. guard 선택·필요성·실제 API 출처 연결은 별도 프로필 코드와 통합 테스트가 검증해야 한다.

## API 시각 해석의 검증 수준

이 정책은 이미 보존된 `kst` → `API_KST_AS_PUBLISHED` 후보 계약에 현대 법정시 근거를 결합한 **파생 채택**이다.2026년 API 절기와 기존 KST fixture가25개 표기에서 일치했다는 직전 실행은 비교 근거이고, 이번 A에서 실제 명식·경계 후보·출처 연결을 다시 검증해야 한다.1989~2026년 모든 절기 분의 외부 천문 정확성을 독립적으로 확인했다는 뜻은 아니다.

공공데이터포털15012690 목록의 새 공개 페이지 열기는 이번 조사에서 실패했고, 그 API 첨부 가이드 원문을 새로 열어 전수 검토했다고 주장하지 않는다. 따라서 전체 역사 API에서 `kst`가 언제나 동일한 역사적 민간시 의미를 가진다는 일반화는 보류한다. 이 한계는 현대 DST0 범위·겨울 guard를 한정한 채택과 구별한다. 직접 실행할 A/B 비교가 다른 시계 기준의 징후를 보이면 해당 이벤트·구간을 `POLICY_UNRESOLVED`로 격리하고 지원 범위를 넓히기 전에 해결해야 한다.

## 계산과 테스트 불변 조건

1. 엄격한 `YYYY-MM-DDTHH:mm` 민간시 분을 파싱하고 비교한다. `new Date(localString)`나 호스트 시간대를 사용하는 파싱을 하지 않는다. 민간시 분과 절기 분을 비교하는 데 UTC 생성은 필수가 아니다.
2. UTC가 부가 산출물로 필요하다면 위 적용 범위에서만 명시적 +09:00 정책을 적용하며, UTC 계산을 사주 경도/태양시 보정으로 취급하지 않는다. 초를 추가로 관측하거나 정확한 절입 순간을 창작하지 않는다.
3. 기존 `PUBLISHED_MINUTE_COMPARISON_ONLY` 불확실성과 입춘의 연·월 상관 후보를 유지한다. 표시 분을 무조건 전/후 어느 쪽으로 정하지 않는다.
4. API 원래 표기·정밀도·응답 지문·서비스/operation/query 참조를 계산용 이벤트의 파생 정책과 함께 출력한다. API 출처를 기존 `KR-KASI-CALENDAR-DATA` TXT 계열로 바꾸지 않는다.
5. UTC 환경과 `Asia/Seoul` 환경에서 같은 가상 입력·데이터셋·정책의 결과가 동일한지 별도 프로세스로 검사한다. 일반 호스트 시간대나 시스템 DST 데이터가 프로필 결과에 관여하면 실패다.
6. 기존 ZI_START는23시 이후 일주 유효 날짜를 익일로 이동한다.2026년말 입력의 유효 일주 날짜가2027년초가 되어도2027년 출생 지원을 뜻하지 않는다. 음력1988년 날짜가 양력1989년으로 환산되는 것도1988년 양력 출생 지원과 다르다. 입력 범위는 변환된 실제 출생 양력 날짜로 검사한다.
7.1950년 대한24:00, 원본 전체의 부분 음력 월, 이전 역사 시간 문제는 보존한다. 이 현대 범위에서 사용하지 않는 이벤트의 문제를 전체 현대 경로의 영구 중단 사유로 삼지 않는다.

## 연결 코드 읽기 검토

`scripts/kasi/local-chart.mjs`의 초기 단계A 구현을 읽었다. API 원문 시간 상태를 삭제하지 않고 별도 `interpreted`에 KST/분 정밀도/정책ID·버전/+540분/UTC null을 기록한다. 출생 정책도 명시 입력이고 기존 Four Pillars composer를 호출한다. 이벤트는 연도별24개와 이전 대설 한 건만 선택하며 출생 범위도 프로필에서 별도로 검사한다. 이 구조는 위 근거의 제한과 부합한다. 호스트 지역시 파싱이나 임의 태양시 보정은 발견하지 않았다.
