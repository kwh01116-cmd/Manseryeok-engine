# Engine completeness reassessment and G0 execution — 2026-10-19 KST

## Direction and evidence standard

The owner's current direction is engine development until further instruction. Existing EP0–EP4 remains **Manseryeok Lab**, an internal calculation/rule verification tool. No Story App, EP5 UI, character, webtoon, visual redesign, personal interpretation or deployment was added. Future product/design work is a separate Astra task; it is not an implied engine deliverable.

Assessment uses actual `src/`, test files, source-gate documents and this exact checkout's execution results. Three statements must remain distinct: **software follows its encoded contract**, **output agrees with independent external evidence at a stated precision**, and **a source/edition is authentic and its field reuse permitted**. None implies the others. Passing a traditional lookup test does not validate predictive effects. No numeric “engine completion percentage” is asserted.

Status vocabulary:

- **IMPLEMENTED_AND_TESTED**: the scoped executable behavior and relevant regression tests passed; external scope caveats remain.
- **PARTIALLY_VERIFIED**: functioning pieces exist but the milestone's source, coverage, policy or independent verification gate is incomplete.
- **RESEARCH_ONLY**: documents or test-only datasets/prototypes, not promoted to supported runtime.
- **BLOCKED_BY_SOURCE_OR_POLICY**: executable promotion withheld for an identified source/interpretation decision.
- **NOT_IMPLEMENTED**: no executable feature; an inventory/spec title is not a resolver.

## G0 architecture and guarantees

Original counterexample: a genuine M1 preview with only `solarTermSourceIds=['FORGED-NONEMPTY']` changed still produces `READY` through generic `deriveM2ChartFactsV2/V3`. The generic v1 gate checked nonempty strings, not whether they were from the selected server fixture. Merely comparing two self-consistent DTOs or adding more strings to an allow-list cannot bind a chart to its calculation.

New `src/validation/trustedKoreanPreview.ts`:

1. Selects the fixed **KOREAN-LAB-KASI-2026-2027-V1** profile internally: existing frozen 49 events, full-year manifest, existing lunar converter/corpus and its 2025–2027 annual edition metadata. Caller cannot supply fixtures, manifest, resolver callback or trusted-source declarations.
2. Checks explicit time policies, including for dates that will be blocked; invokes the existing M1 resolver **once**. Does not create another astronomical, lunar or Four-Pillars calculation path.
3. Independently checks the produced shape/source union/coverage/lunar-source presence against that selected context and uses `copyValidatedKoreanMonthBoundaryTrace(..., events)` to check exact event timestamp/source/precision and candidate correlation. Corpus-wide source attribution never substitutes for an event record.
4. Deep-copies/freezes the result and exposes a frozen receipt/context. A private **WeakMap** recognizes actual issued receipt objects; copied/serialized/fabricated receipt fields are not registration. No request log, file/database storage, global birth-record key or external service was added. Receipt lifetime follows in-process references.
5. `verifyTrustedKoreanLabPreview(receipt, candidate)` compares exact plain JSON data to that execution snapshot, independent of property insertion order. Unknown/missing/extra fields, nonempty fake or mismatched known source, changed candidates/policies/schema/coverage/conversion data, swapped boundary references and foreign execution data are rejected. Getters/toJSON are not used by normal JSON-data comparison. Unchanged serialized data may be verified; receipts themselves are not portable signatures.
6. Trusted v1/v2/v3 wrappers verify before calling existing M2 derivation. A missing/unsupported M2 policy still throws; blocked M1 gives blocked M2 without fabricated metadata. No default school, corrected source replacement or candidate repair occurs. Only after equality succeeds does verification return the identical immutable issued snapshot.
7. Lab HTTP now calls this entry point and verifies before existing factual projections. Its response shape, opt-in EP4, coverage, status behavior and UI are unchanged. No M2 v2/v3 HTTP endpoint or EP5 screen was added.

### Explicit limits

- **Generic functions remain generic.** They assume trusted upstream M1 and retain structural checks; the regression intentionally records that their old forged-nonempty-source example remains `READY`. Their comments now state the guarantee accurately. Consumers needing the fixed Lab guarantees must use the trusted entry points.
- A receipt is an in-process execution capability, not proof about arbitrary external historical DTOs. An arbitrary unissued chart cannot be authenticated without trusted evidence; this boundary rejects rather than recalculating or guessing. Same trusted input/facts are not a second scientific oracle.
- A compromised process/module or incorrectly transcribed trusted fixture is outside this consistency guarantee. Existing digest tests pin repository solar/lunar payloads. Runtime context uses the selected existing annual-edition map; `SolarTermEvent` still lacks a per-row edition field. **Row-to-edition manifest/fingerprint refinement is the next G1**, not an already completed scholarly-authentication gate.
- Source-ID/edition consistency does **not** certify an original document, KASA authority, minute/second truth, copyright status or commercial reuse. The `SELECTED_FIXTURE_AND_EXECUTION_CONSISTENCY_ONLY` guarantee is deliberately narrow.
- HTTP remains private loopback. Production Host/Origin checks, limits/timeouts, CSP, privacy/abuse design and release rights are not completed by G0. No real birth records were used in these checks.
