# 로컬 KASI 1950~2026 전체 수집

## Windows x64 실행 패키지

`Manseryeok-KASI-1950-2026-windows-x64.zip`은 기존 TypeScript Collector로 만든 독립 로컬 실행 패키지다. 공식 배포 Node 22.23.3 Windows x64 실행 파일과 고정 생산 의존성, 빌드된 Collector를 포함한다. Python·Node 별도 설치, 관리자 권한, Git 또는 npm 설치 과정이 필요 없다. 실행 시 인터넷은 KASI 조회에 사용한다. Mac/ARM Windows용 패키지는 아니다.

1. ZIP을 **전부 압축 해제**한다. ZIP 안에서 실행 파일 하나만 열지 않는다.
2. 풀린 폴더의 **`start-kasi-collection.cmd`를 더블클릭**한다.
3. 일반 인증키 **값만** 붙여넣고 Enter. 입력 문자가 보이지 않는 것이 정상이다. URL 전체나 `KASI_API_KEY=`는 넣지 않는다. 이 입력은 환경변수의 다른 키를 사용하지 않고 두 서비스에 공통으로 적용한다. 키는 파일·명령 이력·로그에 저장하지 않는다.
4. 1950·2026년의 24절기와 1월 음양력 응답을 검사하고, 두 연도의 전체 자료를 수집·오프라인 재검증한다. 어느 서비스든 승인/스키마/정밀도/완전성 검사가 실패하면 다음 연도에 진입하지 않는다.
5. 두 표본이 완료되면 전체 수집 여부를 묻는다. 계정의 호출 한도를 확인한 뒤 **`1950-2026`**을 입력하면 77년 수집이 시작된다. 다른 입력은 표본만 보존하고 종료한다.
6. 최종 **`COMPLETE`**와 `summary.json`의 건수를 확인한다. `SAMPLES_READY`, `IN_PROGRESS`, `FAILED`는 전체 완료가 아니다.

특일 정보 **15012690**와 음양력 정보 **15012679**는 각각 활용 승인이 필요하다. 같은 일반키를 쓸 수 있다는 사실이 두 서비스 승인을 증명하지 않는다. 아직 실제 1950년 자료 지원과 이 PC의 모든 응답을 검증한 것은 아니다.

## 대상과 완료 기준

* 양력 기준 **1950-01-01~2026-12-31**, 77년.
* 24절기 **1,848건**과 양력 각 날짜의 음양력·윤달·월 크기·API 간지 **28,124건**.
* 음력 1949년에 속하는 1950년 초 날짜 등은 원래 `lunarYear`를 보존한다. 음력 연도 전체가 1950~2026이라는 뜻이 아니다.
* 월 단위 모드의 최소 요청은 **1,001회**이며 실제 페이지 수·재시도에 따라 늘어난다. 직렬 350ms 간격, 요청별 10초 제한, 일시 오류에 최대 3회 시도를 사용한다. 실행 시간은 서버 응답과 호출 한도에 따라 달라진다.
* 마지막에 77년을 원문→페이지 receipt→정규화 파일 순으로 다시 검사한 뒤 전체 export를 생성한다. 검증이 끝날 때까지 `COMPLETE`를 쓰지 않는다.

`kst`가 없으면 날짜 자료로 남지만 분 정밀도 완료 연도가 되지 않는다. 잘못된 HHmm·날짜·중복·잘못된 황경·페이지 누락은 거절한다. 실제 사용자 제공 1950년 응답에서 `대한 / 19500120 / 2400`이 확인되어, 정확한 `2400`은 원래 날짜와 `24:00`, `timeNotation=AS_REPORTED_2400`으로 수집한다. 같은 날 00:00이나 다음날 UTC로 바꾸지 않으며 사주 경계 해석은 미해결이다. `2401`·`2460`·짧은 `120` 등은 계속 거절한다. 황경이 **없으면** null로 허용하되, **반환된 값이 잘못됐으면** 거절한다. 오류를 없애기 위해 시각·황경을 임의로 채우거나 다른 키/형식으로 재시도하지 않는다.

## 저장·재개·제출

### 1950년 표본에서 KST_HHMM이 발생했을 때

**2026-11-09 정정:** 제공된 원문의 2번째 행 `kst=2400`이 이번 실패 원인임을 확인했다. `KASI-2400-resume-patch.zip`의 `.kasi-build` 폴더를 기존 실행 폴더에 합치고 같은 `start-kasi-collection.cmd`를 실행하면 된다. `.private`는 삭제하거나 교체하지 않는다. 전체 ZIP을 새 폴더에 풀어 사용할 때도 이전 `.private`를 안전하게 보존·이관해야 재수집을 피할 수 있으므로 작은 패치 방식이 우선이다.

이하 진단 방법은 아직 원문이 제공되지 않은 다른 형식 오류에 사용할 수 있다.

이는 성공 응답의 시각 표기가 현재 HHmm 규칙과 맞지 않는다는 뜻이다. 실제 원문을 보기 전에는 선행 0 누락·초 단위·다른 형식 중 무엇인지 단정하지 않는다. `KASI-cache-diagnostic-patch.zip`의 **내용**(`.kasi-build` 폴더, `diagnose-kasi-cache.cmd`)을 기존 실행 폴더에 합친 뒤 `diagnose-kasi-cache.cmd`를 더블클릭한다. 새 폴더에서 실행하지 말고 `.private`를 지우거나 이동하지 않는다.

새 API 요청이나 키 입력 없이 캐시 영수증·원문 해시를 읽고 허용된 절기명, 날짜/시각/황경의 짧은 숫자 표기와 실제 타입, 기존 정규화 오류 코드만 기록한다. 원문 메시지·임의 필드·알 수 없는 문자열은 출력하지 않는다. 원문과 완료 상태, 검사 규칙은 변경하지 않는다. 결과는 `.private/kasi-local-1950-2026/monthly-xml/diagnostic-solar-1950.json`이다. 이 JSON을 비공개 작업에 제공하면 실제 응답 형태를 확인할 수 있다.

진단 보고서의 `PASS`는 개별 행 정규화 결과이며 연간 수집 완료나 정확도·원본 인증이 아니다. 캐시를 못 찾으면 패치가 이전 수집과 같은 폴더에 있는지 먼저 확인한다.

기본 결과 위치:

```text
.private/kasi-local-1950-2026/monthly-xml/
  raw/             성공한 응답 원문, 내용 SHA별 보관
  pages/           키 없는 요청 항목·UTC 시각·스키마·응답 지문
  probes/          표본 보고서
  years/           완료 및 재검증 가능한 연간 자료
  plan.json        77년 수집 범위/모드
  summary.json     이번 실행 상태 및 전체 완료 건수
  export.json      모든 연도를 검증한 경우에만 생성한 전체 JSON
```

창을 닫거나 Ctrl+C로 중단할 수 있다. **같은 폴더에서 같은 실행 파일을 다시 실행**하면 원문 해시를 확인하며 완료 페이지와 연도를 재사용한다. 매번 새 압축 폴더에서 실행하면 이전 체크포인트를 찾지 못한다. 중단 시 lock은 다음 실행에서 종료된 PID인지 확인한 뒤 회수한다. 두 창을 동시에 실행하지 않는다.

손상된 캐시를 정상 자료로 덮어쓰지 않는다. 장애가 발생하면 저장 폴더를 보존하고 안전한 오류 코드와 `summary.json`을 확인한다. 이전 export가 남아 있더라도 현재 summary가 COMPLETE가 아니면 이번 실행 완료로 해석하지 않는다. 디스크/권한 오류로 상태 파일 갱신 자체가 실패할 수 있으므로 콘솔 종료 오류도 확인한다.

`validate-kasi-collection.cmd`는 키 입력/API 호출 없이 전체 저장 자료를 재검증·export한다. 정상 완료 뒤 **`.private/kasi-local-1950-2026/monthly-xml/` 폴더 전체**를 ZIP으로 보관하거나 비공개 작업에 업로드한다. 원문과 receipt 없이 export만 있으면 이 도구의 원문 대조를 재현할 수 없다. 키가 있는 메모장·주소창·환경파일은 묶지 않는다. 원문 데이터 공개 재배포는 이번 작업의 범위가 아니다.

## 월 단위 음양력 조회가 실제로 지원되지 않을 때

`start-kasi-collection-daily.cmd`는 사용자가 명시적으로 고르는 **일별 모드**다. 기본 도구가 실패했다고 자동 전환하지 않는다. 전체 최소 **28,201회**(절기 77 + 음양력 28,124), 추가 페이지/재시도 포함 가능하므로 일일 quota를 반드시 확인한다. quota/접속 오류로 중단되면 한도 회복 후 같은 모드로 재개한다. 무제한 재시도나 자동 밤샘 재실행은 하지 않는다.

일별 결과는 `.private/kasi-local-1950-2026/daily-xml/`에 분리한다. 월별 캐시와 섞지 않는다. 일별 자료 검증은 터미널에서 `validate-kasi-collection.cmd --lunar-mode daily`로 실행한다. 한 모드 안에서 자료가 충돌하면 파일을 임의 삭제하거나 모드를 바꾸지 말고 원인을 먼저 확인한다.

## 개발 저장소에서 같은 동작 실행

Node 22.19+ within 22 (권장 22.23.3), `npm ci`, `npm run kasi:build` 후:

```sh
npm run kasi:local -- wizard
# 이미 안전하게 환경변수를 구성한 비대화형 실행:
npm run kasi:local -- samples
npm run kasi:local -- collect --allow-bulk
# 키 없이 오프라인 검사:
npm run kasi:local -- validate
```

비대화형 실행은 기존 공통키/서비스별 명시 override 계약을 사용한다. `wizard`에서는 입력한 공통키만 사용한다. 형식/모드는 `--format xml|json`, `--lunar-mode monthly|daily`로 명시하며 저장 위치도 분리된다. 전체범위는 이 도구에서 고정되어 있다. 더 넓은 범위를 임의로 요청하지 않는다.

## 검증과 사용 범위

모의 API로 두 표본→전체 77년→오프라인 검증→재개 무중복 경로를 검사한다. 합성 자료는 천문학적 참값이 아니다. Linux에서 Node/CLI/기존 실제 Chromium 검사를 수행하며, 네이티브 Windows CMD·콘솔 붙여넣기·전원 손실·실제 계정의 77년 수집은 별도 미검증이다.

Windows에서는 temp 파일 fsync→rename을 사용한다. POSIX의 디렉터리 fsync는 Windows에서 지원되지 않으므로 그 단계만 생략한다. Windows 전원 손실 시 디렉터리 영속성까지 POSIX와 동일하다고 보장하지 않는다. 시작/재개 시 지문 검사는 유지한다.

API 응답 수집 완료는 1950~2026 출생자 사주 계산 지원이나 원본 판본 인증·상업권 승인으로 승격되지 않는다. `externalOriginalVerification`/`rightsReview`는 UNVERIFIED, G1-P2는 NO-GO이며 기존 M1 지원 범위는 그대로다. 역사적 KST 표기는 당시 민간시/DST 변환으로 간주하지 않는다.
