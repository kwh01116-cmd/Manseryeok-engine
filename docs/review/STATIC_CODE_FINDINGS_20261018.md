## Manual code excerpts used as facts, not assumed behavior

It delegates birth parsing to `parseKoreanChartCliArgs`, accepts JSON <=8192 bytes, and handles invalid input with status 422. It does **not** create a database or explicit file-backed event log. Requests can still be logged by an upstream reverse proxy when deployed.

## Release-grade security checklist (to test later, not "tested")

1. Request from `evil.example` with custom `Host`, `Origin`, JSON `Content-Type`; check CORS/preflight/Host filtering and DNS-rebinding scenario. Do not assume unsetting `Access-Control-Allow-Origin` fully addresses DNS rebinding.
2. Oversize request body 8,193 bytes; fragmented/slow stream; invalid UTF-8, nested JSON, unknown props, object prototype-style keys, duplicate keys, invalid lunar leap dates; request deadline and memory cap.
3. Response no-store, no-store browser caches, optional CDN/proxy logs; pin privacy promise to actually supported controls, not a blanket "zero retention".
4. XSS/CSP test against source IDs and user-provided tokens, unexpected HTML characters; inspect `textContent` use and avoid writing input as `innerHTML`.
5. Chromium accessibility and mobile 320/360/390px, tab/focus order, `<details>` Enter/Space, labels, no color-only meaning, error announcement to screen readers, reduced motion.
6. Source/license inventory with exact URLs/editions, attributed note, allowed storage/reuse, no protected official document copied into release.
7. Integration only after target deployment topology is selected. **No production host, credential or paid runner was provisioned by this review.**
