# 로컬 리포트 저장 중단과 복구

Sprint 8에서는 검증된 결과 파일을 먼저 쓰고 주문에 파일 참조를 기록했다. 이 사이에 환불 상태만 확정되고 서버가 종료되면, 재시작 후 사용자는 열람할 수 없어도 서버에는 암호화 파일이 남았다. Sprint 9는 저장 파일의 주소를 주문 생성 때부터 결정할 수 있다는 기존 계약을 이용한다.

## 복구 기준

전용 저장 디렉터리에는 단일 구매 서버만 쓰기 권한을 갖는다. 서버는 시작할 때 주문 저장소의 쓰기 잠금을 확보하고 암호화된 주문 상태를 인증한다. HTTP 수신과 생성 재개 전에 소유자와 주문의 기존 멱등키로 HMAC 파일 주소를 다시 구한다. 주문에 파일 참조가 있으면 두 주소가 일치해야 한다. 이전 Sprint에서 이미 만든 주문에도 같은 절차를 적용한다.

| 주문의 확정 상태 | 파일 처리 |
|---|---|
| 완료·열람 가능 | 연결된 파일이 있어야 한다. 실제 열람 시 복호화와 claim 검증을 다시 수행한다. |
| 결제 확인·생성 시도 중·재시도 가능 | 이미 확정한 파일을 보존한다. 복구 작업은 같은 파일을 인증하고 내용이 같을 때 재사용한다. |
| 취소·환불·명시적 삭제·생성 최종 실패 | 취소/권한 회수 상태가 삭제 의도를 나타낸다. 파일 참조 기록 전에 멈췄더라도 해당 소유자·주문의 파일만 인증해 제거한다. 같은 요청을 다시 처리할 수 있다. |
| 생성 시도 없음 | 연결되지 않은 완성 파일이 발견되면 시작을 중단하고 운영자 확인을 요구한다. |

정상 작동 중에도 취소·환불·삭제 상태를 확정한 다음 파일을 지운다. 저장 중 늦은 생성 완료가 도착하면 같은 주문의 취소 상태를 다시 확인한다. 파일 삭제가 실패하면 성공 응답을 주지 않는다. 접근 권한은 이미 회수됐으며 다음 실행에서도 정리 대상이 된다.

재시작 시 서버는 해당 주문의 저장 중 임시 파일과 잠금 파일만 회수한다. 소유자가 다른 파일, 출처 불명 파일, 링크, 손상된 키나 파일을 만나면 필요한 곳에서 처리를 중단한다. 주문 원장이 지정하지 않은 파일을 일괄 삭제하지 않는다. 원장의 임시 암호문은 확정 상태 파일의 인증이 끝난 뒤에만 제거한다. 최초 기록부터 중단되어 임시 파일만 남으면 운영자 검토가 필요하다.

## 검증 방법

`test/sprint9-recovery.test.mjs`는 임시 디렉터리에 가상 사용자 두 명의 주문을 만든다. 부모 프로세스가 목표 지점 도달 통지를 받은 뒤 테스트 자식 프로세스를 실제로 강제 종료한다. 매 시나리오에서 서버를 두 번 열어 반복 처리, 실제 파일 수, 다른 소유자의 결과·권한을 확인한다.

| 중단 지점 | 재시작 전 확인 | 재시작 후 기대 |
|---|---|---|
| 생성 취소를 기록하고 파일 쓰기 전 | 다른 사용자의 완료 파일 한 개 | 취소된 주문 파일 없음 |
| 결과를 저장하고 주문 참조를 연결하기 전 환불을 기록 | 완료 파일 두 개 | 환불 주문 파일만 제거, 요청자는 계속 열람 불가 |
| 완료된 주문의 삭제 요청을 기록하고 파일 제거 전 | 완료 파일 두 개 | 삭제된 주문 파일만 제거, 재삭제 허용 |
| 임시 리포트 파일 기록·동기화 직후, 최종 이름으로 변경 전 | 다른 사용자의 결과와 대상 주문의 임시·잠금 파일 | 임시·잠금 파일 회수, 재시도 한 번으로 완료 |
| 결과를 저장하고 주문 참조를 기록하기 전 | 완료 파일 두 개 | 같은 암호문을 재사용해 주문과 연결 |

나머지 두 검사는 등록되지 않은 파일과 잘못된 리포트 키로 시작을 거절하는지 확인한다. 잘못된 키로 접근 권한을 복구하거나 출처를 확인할 수 없는 사용자 파일을 삭제하지 않는다.

검증 범위는 단일 로컬 서버의 프로세스 강제 종료다. 전원 장애, 파일시스템 손실, 백업 사본의 삭제, 동일 OS 계정의 악성 운영자, 여러 노드가 같은 저장소를 공유하는 환경에는 추가 검증이 필요하다. 명시적 리포트 삭제는 해당 결과 파일에 적용한다. 별도로 남는 주문·검토 정보와 백업의 보존 기한은 실사용 승인 전에 정해야 한다.
