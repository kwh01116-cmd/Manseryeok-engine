# Sprint 9 비공개 평가 개인정보·보안 게이트

**허용 환경은 감독 가능한 로컬 PC에서 가상 명식과 합성 답안을 사용하는 INTERNAL_QA다. 실제 참가자 평가와 개인 출생정보 수집은 BLOCKED다.** 평가 자료에는 미리 정한 가상 명식만 들어 있다. 연구자가 자신의 평가나 모델의 평가를 인간 응답으로 저장해서는 안 된다.

## 수집 범위와 안내문 초안

연구 목적은 어느 글이 더 구체적으로 읽히는지, 어느 장에서 설명이 부족한지, 전문가가 어떤 근거에 이견을 갖는지 알아보는 것이다. 참가자와 사람이 읽기 전의 자체 검사는 별도 기록한다.

- 저장 대상은 가명 참여 ID, 사례 ID, 역할, 배정, 동의·제출 시각, 질문별 점수·선택·자유 의견이다. 전문가의 자격 유형·경험 구간·해석 관점은 선택지로 받으며 각 항목에서 응답을 보류할 수 있다. 지금은 자격 증명을 확인할 경로가 없다.
- 본인이나 타인의 실제 생년월일·출생 시각, 연락처, 사례 상담 기록을 이 평가에 입력하지 않는다. 다른 사람의 출생정보를 대신 제출하는 절차도 없다. 지정된 가상 입력과 의견을 별도 보관한다.
- 참여자는 안내문을 읽고 정확한 동의 버전에 동의한 후 배정 자료를 볼 수 있다. 블라인드 비교에는 대조 자료가 섞인다는 점을 미리 안내하고, 마지막에 그 구성을 설명한다. 운영자 CLI가 사람의 동의를 대신할 수 없다.
- 자유 서술을 외부 LLM, 로그, 분석 서비스에 보내지 않는다. 입력 제한과 화면의 텍스트 렌더링은 위험을 줄이지만 자유 서술 속 개인 식별 가능성을 완전히 제거하지 못한다. 외부 공유와 이메일 발송을 하지 않는다.

## 초대와 권한

초대권은 로컬 운영자가 명시적으로 발급한다. 기본 1회, 최대 5회이며 기본 만료 24시간, 최장 7일이다. 사용자에게서 역할·사례·운영 모드를 받지 않는다. 초대권 원문은 운영자가 지정한 신규 비공개 파일에만 표시되며, 서버는 HMAC 색인으로 대조한다. 테스트를 마치면 운영자는 발급 파일을 지운다. 서버가 초대권 사용 수 차감과 세션 생성을 같은 암호화 저장 트랜잭션으로 처리한다.

참가자 세션은 초대권과 별도로 발급한 난수를 사용한다. 만료는 초대권과 24시간 중 먼저 오는 시각이다. 서버는 토큰의 HMAC 색인, 소유 참여 ID, 만료와 취소 상태를 검증한다. 참가자가 자의로 다른 사례·후보·질문·참여 ID를 연결할 수 없다. 초대권을 취소하면 기존 세션의 접근도 끝난다. 무효·만료·소진 초대권이 동일한 거절 결과를 받는다.

브라우저는 루프백 세션 쿠키로 접근한다. HTTP 응답은 `HttpOnly; SameSite=Strict` 쿠키, Origin 검증과 CSRF, 고정된 정적 파일 목록, 콘텐츠 보안 정책, 응답 캐시 차단을 사용한다. 참가자에게 관리 API가 없다. 운영자는 파일 소유 권한이 있는 컴퓨터에서 직접 관리 CLI를 실행하며 서버와 동시 쓰기는 차단된다. 다른 PC에 공개하거나 TLS 종료 프록시에 연결하는 행위는 별도 승인이 필요하다.

## 보관과 철회

이 연습 환경에서는 참여 생성 시점부터 7일 후 기록을 만료시킨다. 읽기 권한은 세션·초대 만료와 동시에 끝난다. 활성 프로세스는 매시간 만료 데이터를 정리하고, 서버 또는 관리 CLI를 열 때와 통계·내보내기를 요청할 때도 정리한다. 꺼진 PC는 만료 시각에 파일 삭제를 실행할 수 없다. 다음 시작 시 정리가 성공해야 서비스가 열린다. 주기적 정리 쓰기가 실패하면 접근을 차단하고 운영자가 저장소 상태를 확인해야 한다.

완료 전후 모두 참가자 화면에서 철회할 수 있다. 세션을 잃었을 때는 로컬 감독자가 승인된 가명 참여 ID를 확인하고 삭제할 수 있다. 운영자에게 참여 신원 복원 능력이 있다고 가정하지 않는다. 등록자 식별·대리 삭제 요청 확인, 초대권 파일의 실제 전달·회수 절차는 실참여 이전에 마련해야 한다.

활성 레코드는 AES-256-GCM, 접근 색인은 별도 키의 HMAC을 사용한다. 초대권 또는 출생정보의 해시를 익명화 수단으로 취급하지 않는다. 기존 로컬 vault의 임시 기록·파일 잠금·손상 거절 정책을 재사용한다. 운영자 키 파일은 이 PC의 별도 비공개 디렉터리에 보관하며 접근 가능한 OS 계정이 해당 자료를 열 수 있다. 로컬 삭제는 메모리·백업·디스크의 물리적 영구 소거를 보장하지 않는다.

**운영자 내보내기는 수동 관리 사본이다.** 활성 데이터 철회와 별개로 운영자가 모든 평문 내보내기 사본을 지우고 확인해야 한다. 현재 저장 구조에는 외부 복사본, 스크린샷 또는 백업을 일괄 폐기하는 정책이 없다. 실제 개인정보가 포함된 내보내기를 허용할 수 없다.

## 실참여 전 점검표

| 점검 항목 | 내부 합성 연습 | 실참여 게이트 |
|---|---|---|
| 승인된 대상·모집 방식·독립 전문가 자격 확인 | 모집 0명 | BLOCKED — 사용자 승인과 독립 대상 확보 |
| 참여 설명·자유로운 철회·보관 기간 | 버전 있는 안내문과 철회·삭제 실행 | BLOCKED — 안내문과 책임 운영자 검토 |
| 연구 데이터와 출생정보 분리 | 가상 사례 ID만 접수 | 실제 출생정보 별도 승인 필요, 현재 금지 |
| 참가자·운영자 접근 분리 | 루프백 쿠키, HMAC, 운영자 로컬 CLI | BLOCKED — 감독 절차·기기 관리·OS ACL 검사 |
| 운영자 파일·키·수출물·백업 삭제 | 암호화 저장, 주기 정리, 수동 사본 관리 | BLOCKED — 키 관리·백업·삭제 요청 대응과 점검 |
| 원격 접근·동의·제보·사고 중지 | 가상 연습에 한정 | BLOCKED — 실제 참가자 승인·사고 대응 책임, 호스팅 시 별도 보안 검토 |
| 실제 판매·결제·공개 배포 | 차단 | NO-GO |
