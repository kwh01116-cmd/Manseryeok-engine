# U1 EP3–EP5: Korean factual scroll-story blueprint (design-only)

**Status:** script/interaction specification; **not** implemented, rendered or usability tested. Baseline verified local-only EP0 ("왜 계산됐나요"), EP1 (일간), EP2 (절입 기반 월지). The product is a Korean cultural storytelling interface, not science-backed predictions or advice. No animation/audio/image asset is authorized or generated by this spec.

## Global narrative contract

- Every on-screen statement must be either **M1 deterministic calendar fact**, **M2 traditional-rule lookup**, or **interpretation / unsupported**. Only the first two may appear as assertive UI facts, with the kind of evidence visible.
- All facts bind to `preview.candidates[i].*` or versioned `ChartFacts` candidate paths. No text implies two possible Lichun candidates have been resolved.
- `sourceIds` displayed in expanded "근거" panel; school choice/version shown for disputed M2 relations; translations are consistent Korean explanatory language without fake precision.
- Never infer a user's profession, finances, love life, diagnosis, fate, personality or lifespan from month/day elements. No personalized claims under the guise of information.
- Text-only rendering should work with no animation, low-bandwidth, screen readers and reduced motion. Aesthetic defaults for later art: restrained ink-and-paper/hangul labels and small reversible motion; **do not make visually flamboyant predictions**.

## EP3 — 사주 네 기둥의 오행 라벨

**Question:** "이 명식에서 각 천간·지지의 기본 오행 분류는 무엇일까?"

Scene flow:
1. Hook: "여덟 글자를 하나씩 보면, 각각 전통적인 오행 이름이 붙어 있습니다."
2. Four-pillar grid: year/month/day/hour (천간, 지지 각각); tab/focus selection discloses `sourceFactRef`, classification provenance, selected day/hour policy.
3. Two states: `DEFINITE` one candidate; `PUBLISHED_MINUTE_AMBIGUOUS` **two side-by-side or toggle candidates**, *same visual scale*, no default winner.
4. Explain: "오행 라벨은 분류표의 이름입니다. 숫자가 많다고 강하거나 유리하다는 뜻은 아닙니다."
5. CTA: "어떤 규칙으로 붙었나요?" opens existing evidence, without shifting focus unexpectedly.

Data: existing `HEAVENLY_STEMS` / `EARTHLY_BRANCHES` deterministic nature tables **only**, after verifying source rule and maintaining exact `candidateIndex`. No 五行 score, radar chart or personality card. If a lookup is missing, explicit "근거 미확인" rather than empty/silent placeholder.

Acceptance: preserve all eight visible glyphs, count labels only when shown as counts-of-characters (not effective qi); mobile widths 320/360/390 and keyboard tab order; screen reader reads label and role, not color alone. Avoid introducing additional calculation code in the UI.

## EP4 — 지장간은 '안에 숨어 있는 천간' (M2 opt-in)

**Question:** "지지는 한 글자지만, 전통 자료에는 어떤 천간 구성원이 기록돼 있을까?"

Scene flow:
1. Four branch tiles; optional one expanded branch at a time, no random narrative.
2. Expanded tile displays all hidden stems **and** their computed 십성 relative to a specified day master, with MAIN_QI vs OTHER exactly matching `M2-HIDDEN-STEMS-CLASSIC-MEMBERS-MAINQI-V1`.
3. Footnote: "본기/나머지 표기는 선택된 전통 배열의 표시 방법입니다. 계절의 실제 세기나 사람의 성격을 수치화한 결과가 아닙니다."
4. Each member toggles its per-rule `sourceIds` and exact `ChartFacts v1` factRef.
5. "같은 글자에 다른 학파 해석" section stays **disabled** until a second fully reviewed profile exists; do not fabricate rival outputs.

Failure states: missing school-policy selection shows a choice/unsupported notice, not a default table; invalid/unknown birth returns NO CHAPTER; Lichun two alternatives are distinct, not merged; V1 schema absence never auto-promotes to V2.

Acceptance: all 10×12 hidden-stem ten-god primitive matrix tests remain green once executable; tab/focus, no color-only evidence, primary text attribution; no birth input sent to analytics.

## EP5 — 관계는 겹쳐 보인다 (M2 V2/V3 opt-in)

**Question:** "여러 지지 사이에 어떤 전통 분류 관계가 *표시되어* 있을까?"

Scene flow:
1. A factual mini-graph of **four source pillars** connected by *independent* relation cards. Relationship labels always cite exact pillar indices and source rule IDs.
2. Same pair may have multiple cards (e.g. 巳申: 合/破/刑; 寅亥: 合/破). Do not draw one triumphant "합" line that hides another source statement.
3. Triad memberships list all **three expected branches** and all occurrence indices; if missing member, show its outline as **absent**, never invent it. Three members present is "구성원 확인", **not** "합화 성립".
4. Two candidate clocks remain separate candidate views, each with its own pair and triad graph and source factRefs. Switch state does NOT recompute an unknown policy.
5. Disclosure: "관계의 존재 여부를 분류한 것입니다. 실제 영향·길흉·합화 여부는 이 화면에서 판단하지 않습니다."

Acceptance: 0,1,2,3+ relational overlaps; 4 same-branch duplicate; directed Xing arrows; nonadjacent pillars; 2-vs-3 distinct Sanhe; `辰戌丑未` 4-member earth case explicitly NOT ASSUMED. Fallback text diagram for screen readers; accessible arrow labels include "from" and "to" roles in Korean; 320px viewport safe.

## Review & testing protocol

Copy-review in Korean by reader unfamiliar with 사주: ask them to distinguish "사실 분류" vs "운세". If >1 in 5 incorrectly believe "강약/길흉이 판정됐다", revise copy before executable UI. This threshold is an **internal proposed UX gate**, not an established research benchmark. Check 320/360/390/768px, keyboard, Enter/Space in native details, ESC focus if dialog later exists, `prefers-reduced-motion`, no analytics of raw birth dates, no blurred error results. UI implementation must be **one safe chapter per tested slice**, not one unreviewed 3-chapter push while Actions quota is exhausted.
