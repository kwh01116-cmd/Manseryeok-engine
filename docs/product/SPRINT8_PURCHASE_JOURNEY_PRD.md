# Sprint 8 — 로컬 구매·생성·재열람 여정

상태: **LOCAL TEST PROTOTYPE**. 고정 계획 `SAJU-ROADMAP-V1 / 2026-11-15`의 Sprint 8 구현이다. Sprint 9의 실제 고객·전문가 검토와 Sprint 10의 판매 승인을 대신하지 않는다. `PAID_REPORT_READY=NO-GO`, 실제 판매 상태는 `NOT_FOR_SALE_YET`이다.

## 제공하는 경험

단일 상품 가칭은 **나의 사주 해석 리포트**다. 가격·결제 사업자·공개 출시일을 정하지 않는다. 기존 Sprint 7의 선택형 전통 역할 해석을 여섯 장의 리포트로 제공한다. 기존 명리 정책과 계산 코어는 이번 여정에 맞춰 변경하지 않는다.

1. 상품 소개: 무료 원국·기초 구조·미리보기와 향후 본문 구성을 구분한다. 현재 시제품이라는 표시를 유지한다.
2. 출생정보: 양력/음력, 윤달, 출생 시각/시각 미상, 지원 시계 프로필, 일주 변경·시주 천간 기준을 직접 입력한다. 대운·세운·월운은 선택 항목이며 성별이나 조회 연도를 추정하지 않는다.
3. 입력 확인: 서버가 계산한 상태, 원국 후보 수, 장별 제공 범위, 필요한 정보와 정책을 확인한다. 확인하지 않은 입력으로 주문을 만들지 않는다.
4. 무료 결과: 원국·일간·기초 설명을 제공하고 실제 상품은 판매 준비 중으로 표시한다. 별도 색상과 문구로 구분한 **테스트 구매 여정**만 진행할 수 있다.
5. 결제·생성: 서버의 독립적인 주문·결제·생성·환불 상태를 표시한다. 실제 진행률을 알 수 없으므로 임의의 퍼센트는 표시하지 않는다.
6. 열람·보관함: 기존 Sprint 7의 claim과 문장을 그대로 렌더링한다. 제한적 해석과 보류를 표시하고, 정책·claim 식별자는 접을 수 있는 상세 근거에 둔다. 새로고침·서버 재시작 후 동일 게스트 세션으로 저장된 결과를 다시 확인한다.

## 판매 승인과 테스트의 분리

실제 상품의 콘텐츠·결제 통합·법률/운영·공개 출시 승인은 모두 false다. 웹 버튼이나 요청 매개변수가 이 승인을 바꾸지 않는다. 실제 주문·결제 경로는 서버에서 거절한다. 테스트 Provider의 금액은 판매 가격이 아닌 개발용 fixture다. 실제 PG, 결제 키, LLM, 공개 배포는 사용하지 않는다.

테스트 승인 화면 자체는 결제 증거가 아니다. 서버가 검증한 Provider 이벤트만 결제 상태를 바꾼다. 결제·생성·환불의 중복과 순서 충돌은 상태 모델에서 처리한다. 같은 주문의 결과가 여러 번 생성되면 안 되며, 환불로 회수된 접근 권한을 늦은 승인 이벤트가 되살리면 안 된다.

## 입력·제공 적격성

원국 계산 성공은 전체 유료 리포트 제공 성공과 다르다. 기존 장별 LIMITED/HOLD와 자료·시계 정책의 지원 범위를 유지한다. 1988년 DST 누락 시각을 다른 시각으로 옮기지 않고, 중복 시각의 오프셋을 임의로 고르지 않는다. 시각 미상은 정오로 대체하지 않는다. 1950~1961 및 2027 음력의 기존 미지원/자료 부족 상태도 유지한다.

지원하지 않는 입력에는 미리보기 단계에서 이유를 제공하고 테스트 구매를 차단한다. 입춘의 서로 다른 원국 후보와 토왕의 같은 원국·계절 대안을 혼동하지 않는다. 어떤 경계 후보도 편의를 위해 자동으로 제거하지 않는다.

## 개인정보와 게스트의 한계

실제 고객정보를 받는 제품이 아닌 가상 입력 검증용 로컬 서버다. 서버가 발급·검증한 게스트 쿠키와 소유권을 사용하며 클라이언트의 actor ID를 인증 근거로 사용하지 않는다. 출생정보·세션 토큰을 URL이나 브라우저 저장소에 넣지 않는다. 테스트 입력과 결과는 서버 저장소에서 암호화한다.

게스트 세션만으로 영구 보관·다른 기기 복구를 보장하지 않는다. 세션·리포트 만료, 삭제, 무결성 오류는 명시적으로 실패한다. 로컬 파일 저장은 운영 DB·회원 인증·비밀 관리·백업 삭제를 완성한 것이 아니다.

## 화면 품질과 검증 기준

- 기존 웹 화면의 `leaf / paper / ink` 색상과 vanilla HTML/CSS/JavaScript 구조를 재사용한다. 외부 폰트나 이미지·새 프레임워크가 필요하지 않다.
- 입력에는 실제 label을 제공하고 키보드 포커스·본문 건너뛰기·오류 알림·접기 가능한 근거를 지원한다.
- 데스크톱과 작은 화면에서 입력·리포트·상태·환불 동작을 확인한다. 버튼과 본문이 가로로 잘리거나 겹치지 않아야 한다.
- 서버 상태를 화면에 반영하며 입력을 수정하면 이전 미리보기를 무효화한다. 서버와 생성기의 실패를 일반적인 긍정 문장으로 숨기지 않는다.
- HTML에 결과를 임의 삽입하지 않고 DOM `textContent`로 렌더링한다. 게스트 토큰을 JavaScript에서 읽을 수 없어야 한다.
- 실제 Chromium에서 확인한 결과와 스크린샷은 실행 기록에 별도로 남긴다. 이 PRD의 기준 자체를 테스트 통과로 계산하지 않는다.

## 제외 범위

실결제·운영 PG·계정/이메일 복구·운영 DB·법률상 환불 조건 확정·실제 고객/전문가 베타·콘텐츠 판매 승인·공개 배포는 이번 구현에 포함하지 않는다. 환불은 실제 금전 이동 없는 상태 모델 검증이며, 맞춤형 상품을 이유로 환불 불가라는 규칙을 추가하지 않는다.
